Autonomous Agent Build Requirement List
1. Overview

The Autonomous Agent is a trading bot built to assist users in identifying meme coin trends, making trades, analyzing tokens, and managing their trading positions via voice and text. The bot will be integrated with Telegram, using OpenAI's Realtime API for natural language understanding and interaction. MongoDB will serve as the primary data store, holding various records for user activity, trending tokens, and transaction details. This build will be modular and highly structured for easy development and scalability.
2. Core Components & Features
2.1 User Interaction System
2.1.1 Trigger Activation

    User Registration: Users must register before using the bot. On first use, they are prompted to register by providing basic info like their Telegram ID and username.
    Wallet Creation: Upon registration, three wallets (Ethereum, Base, and Solana) are automatically created for the user. The wallets are encrypted and saved under the user's Telegram ID in usersCollection.

2.1.2 User Prompts and Intents

    Voice and Text Activation: Users can activate the bot by sending a voice note or typing phrases like "hey katz" (in any loose format).
    Intents Handling: Based on user prompts, OpenAI processes intents such as:
        FIND_MEME_GEMS: Identify trending meme tokens.
        BUY_MEME_COIN: Execute token purchases.
        SELL_MEME_COIN: Execute token sales.
        MONITOR_POSITIONS: Check and monitor active user trading positions.
        ANALYZE_TOKEN: Analyze token quality and metrics.
        SUGGEST_TOKENS: Suggest meme tokens based on user trade history and trends.
        ENABLE_AUTONOMITY: Enable autonomous AI trading.
        DISABLE_AUTONOMITY: Disable autonomous AI trading.

2.1.3 Automated User Prompts

    Random Time Trigger: When a user registers, calculate 5 random times during the day to prompt them with an OpenAI-formatted message to interact.
        Example questions include:
            "Would you like to find which meme coins are hot on the markets today?"
            "Would you like me to suggest some meme tokens for you?"

3. Functional Requirements
3.1 Core Functions & Processes
3.1.1 findMemeGems Function

    Purpose: Fetch trending meme coins across the market.
    Data Sources: Use APIs like Dextools, Dexscreener, Pumpfun, and Moonshot.
    Output:
        Present a user-friendly result formatted through OpenAI.
        Save trending data in:
            userTodaysTrending: Document specific to each user's trending tokens for the day.
            TrendingRecords: Document that tracks trending tokens for each day.

3.1.2 buyMeme Function

    Trigger: Activated by the BUY_MEME_COIN intent.
    Flow:
        Prompt the user to confirm details like the token address and the amount to buy.
        Execute the purchase on the selected blockchain (Ethereum, Solana, or Base).
        Save transaction details in swapRecords.
        Generate Transaction Certificate: After purchase, generate a certificate (via a canvas) that includes details like token address, amount bought, and price.
        Return formatted results to the user via OpenAI.

3.1.3 sellMeme Function

    Trigger: Activated by the SELL_MEME_COIN intent.
    Flow:
        Confirm details such as token address and amount to sell.
        Execute the sale on the selected blockchain.
        Save the transaction in swapRecords.
        Generate Transaction Certificate: Similar to the buyMeme function, generate a certificate after selling.
        Return formatted results to the user via OpenAI.

3.1.4 monitorPositions Function

    Trigger: Activated by the MONITOR_POSITIONS intent.
    Purpose: Retrieve all active trading positions.
    Analysis:
        Analyze token health and performance using the analyzeToken function.
        Use metrics like token price history, holder growth, and community engagement.
        Present a comprehensive view to the user.

3.1.5 analyzeToken Function

    Purpose: Evaluate the quality and security of a token.
    Data Sources:
        Fetch metrics like price, trading volume, community size, and liquidity pool status.
        Conduct a Security Scan:
            Check if the liquidity pool (LP) is locked.
            Check for token bundling or suspicious deployer activity.
        Ranking Mechanism: Rank tokens based on volume history, holder growth, and sentiment analysis.

3.1.6 suggestTokens Function

    Trigger: Activated by the SUGGEST_TOKENS intent.
    Flow:
        Retrieve user trading history from swapRecords.
        Compare user-traded tokens to trending tokens from TrendingRecords.
        Generate token suggestions and provide reasons for each recommendation.
        Present the top five suggested tokens based on metrics and analysis.

3.1.7 createPosition Function

    Purpose: Create a timed order for automatic execution.
    Flow:
        Store the order in autonomousOrdersRecords.
        Include parameters like token address, action type (buy/sell), amount, price target, and execution time.

3.1.8 autonomousOrderExecutor Function

    Purpose: Execute autonomous buy/sell orders.
    Execution:
        Runs every minute to check autonomousOrdersRecords for pending orders.
        Execute orders when conditions are met and update swapRecords with executed details.

4. Database Schema and Requirements
4.1 MongoDB Documents
4.1.1 usersCollection

    Structure:

    const userDocument = {
      telegramId: userInfo.id,
      username: userInfo.username,
      wallets: {
        ethereum: [{
          address: ethereumWallet.address,
          encryptedPrivateKey: ethereumWallet.privateKey,
          createdAt: new Date()
        }],
        base: [{
          address: baseWallet.address,
          encryptedPrivateKey: baseWallet.privateKey,
          createdAt: new Date()
        }],
        solana: [{
          address: solanaWallet.address,
          encryptedPrivateKey: solanaWallet.privateKey,
          createdAt: new Date()
        }]
      },
      settings: {
        defaultNetwork: 'ethereum',
        notifications: {
          showInChat: true
        }
      },
      autonomousMode: false,
      registeredAt: new Date()
    };

4.1.2 TrendingRecords

    Purpose: Document trending meme tokens for each day.
    Fields: Date, token symbol, address, and chain.

4.1.3 userTodaysTrending

    Purpose: Store trending tokens specific to each user for a given day.
    Fields: User ID, date, list of tokens (symbol, address, chain).

4.1.4 swapRecords

    Purpose: Store individual transaction details.
    Fields: User ID, token details, action (buy/sell), amount, price, timestamp, and network.

4.1.5 autonomousOrdersRecords

    Purpose: Store orders to be executed autonomously by the bot.
    Fields: User ID, token details, action (buy/sell), amount, target price, scheduled time.

5. Module and Folder Structure
5.1 Folder Structure Overview

    commands: Contains openai.js - entry point for handling user prompts and intents.
    modules: Each core function has its own file:
        findMemeGems.js
        buyMeme.js
        sellMeme.js
        monitorPositions.js
        analyzeToken.js
        suggestTokens.js
        createPosition.js
        autonomousOrderExecutor.js
    utils: Utility files for data formatting, encryption, and error handling.
    services: Integration services for API calls:
        apiClients.js for Dextools, Dexscreener, Moonshot.
        openaiService.js for OpenAI Realtime API interaction.
    database: Files for managing MongoDB connections and schemas.

6. Advanced Functionality and Safety
6.1 Automated AI Trading Control

    User Control:
        Users can enable or disable Autonomous AI Trading.
        ENABLE_AUTONOMITY and DISABLE_AUTONOMITY intents manage the activation and deactivation of autonomous trading mode.
    Verification: Before executing any trade, the bot verifies if autonomous trading is enabled. If not, prompts the user to enable it if necessary.

6.2 Safety Checks

    Liquidity and Security:
        analyzeToken function performs security checks to ensure tokens are safe for trading.
        Validate LP lock status and look for signs of token bundling or suspicious behavior.

    Error Handling:
        Provide detailed error messages for users if an action cannot be completed.
        Retry logic for failed actions, ensuring the user is informed of any steps they need to take.

7. User Experience and Enhancements
7.1 Transaction Certificates

    Purpose: Provide users with proof of each transaction.
    Details:
        Certificates are generated using a canvas with transaction-specific information such as token, amount, price, and network.
        Certificates are formatted through OpenAI before being delivered to the user.

7.2 User Guidance

    Interactive Prompts: Guide users through each interaction.
        For example, when analyzing tokens, explain the metrics and provide a conclusion for ease of understanding.
        Suggestions and Analysis: Present reasons behind suggested tokens, offering data-driven insights.

8. Development Resources
8.1 Tools & APIs

    APIs:
        Trending Data: Dextools, Dexscreener, Pumpfun, Moonshot.
        Voice and Text Processing: OpenAI Realtime API.
    Frameworks and Libraries:
        Node.js for the bot backend.
        Telegram Bot API for messaging.
        MongoDB for data storage.
        Canvas for generating certificates.
        Web3.js or ethers.js for blockchain interactions.
